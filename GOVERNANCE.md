# Governance

This document describes how the Stellar Bounty Board project is maintained and how
community members can take on additional responsibilities.

## Roles

| Role          | Description                                                                 |
| ------------- | --------------------------------------------------------------------------- |
| **Owner**     | Holds full administrative control of the repository and makes final decisions. |
| **Maintainer**| Reviews and merges pull requests, manages issues, and guides the project.    |
| **Triage**    | Helps sort, reproduce, and label issues and pull requests.                  |
| **Contributor**| Submits pull requests and participates in discussions.                      |

## Becoming a Co-maintainer

The project welcomes contributors who want to take on more responsibility. If you
are interested in helping with PR reviews, issue triage, or codebase upkeep:

1. Open a GitHub issue expressing your interest and the areas you would like to help with.
2. Reference your prior contributions (merged PRs, issue work) so maintainers can
   evaluate your familiarity with the codebase.
3. The owner will review the request and respond on the issue.

Access is granted at the owner's discretion. Depending on the request, the owner may
grant **triage** permissions first, move to **maintainer** after a trial period, or
decline with feedback. Granting or revoking access is done through the repository's
**Settings → Collaborators** page and does not require a code change.

## Expectations for Maintainers

- Review incoming pull requests promptly and constructively.
- Keep the review queue moving and help contributors succeed.
- Help triage, reproduce, and label bug reports and feature requests.
- Maintain test coverage, documentation, and code quality.
- Follow the project's [Contributing](CONTRIBUTING.md) guidelines and
  [Conventional Commits](CONTRIBUTING.md#conventional-commits) standard.
